## Known Discrepancies and Root Causes

### 1. ~1.12° Ayanamsa Offset (5 subjects)

| Discrepancy | Root Cause | Impact | Resolution |
|---|---|---|---|
| 5 subjects have ~1.12° offset in all planetary longitudes | Exported with **Pushya Paksha** ayanamsa (SIDM_TRUE_PUSHYA) instead of Traditional Lahiri (SIDM_LAHIRI_1940) | Sign/nakshatra/pada mismatches near boundaries; navamsa differences | Re-export from JHora with Traditional Lahiri setting |

**Affected subjects:** Maxim_Ccitovski, Tijaneta_TyGy, MixAll_DrKhans, Alexxandra_ExShokutna, J_G

**Evidence:** Maxim's export shows ayanamsa = 22°28'40" (Pushya Paksha for 1982) vs Nikola's 23°42'45" (Lahiri 1940 for 1990). The ~1°7' difference matches the known Pushya Paksha-to-Lahiri offset.

### 2. Research Doc vs Implementation Discrepancy

| Setting | Research Doc (Incorrect) | Actual JHora (Verified) | Status |
|---|---|---|---|
| Node type | MEAN_NODE | TRUE_NODE | Implementation correct; research doc wrong |
| Ayanamsa | SIDM_LAHIRI | SIDM_LAHIRI_1940 | Implementation correct; research doc wrong |

**Root cause:** The research doc (`docs/swisseph_vedic_research.md`) was based on web research and P.V.R. Rao's 2005 posts (which recommended mean nodes). JHora's default changed to true nodes in later versions. The v2.0.1 session verified against actual export data and corrected the implementation.

### 3. Lagna ~12 arc-min Tolerance

**Root cause:** Sidereal time / delta-T model difference between Swiss Ephemeris and JHora. JHora uses its own non-linear ayanamsa module and may handle delta-T differently (including the double delta-T issue).

**Mitigation:** With .se1 files + custom ayanamsa matching JHora's non-linear model, could be reduced to <2 arc-sec.

### 4. Moon ~35 arc-sec Tolerance

**Root cause:** Moshier ephemeris fallback (when no .se1 files) has ~3 arc-sec accuracy for Moon. The double delta-T issue adds ~30 arc-sec. Combined tolerance set to 35 arc-sec.

**Mitigation:** With .se1 files: ~3 arc-sec. With .se1 files + delta-T fix: ~5 arc-sec.

### 5. Double Delta-T Issue

**Root cause:** JHora/DrikPanchang pre-convert UT to TT, then pass TT to `swe.calc_ut()` which adds delta-T again. This advances computation time by ~69 seconds (2025).

**Impact:** Moon shifted ~0.5 arc-min; dasha timing shifted ~4-13 hours.

**Status:** Not currently replicated in the project. Within tolerance for natal positions except Lagna.
